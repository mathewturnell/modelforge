Connect Modal

Modal is optional. The public alpha can send only the bundled Synthetic Threshold Lab to a fixed, small CPU function. It does not upload a dataset or download a model.

1. Install and authenticate

python3.12 -m venv .venv
.venv/bin/python -m pip install 'modelforge-workbench[modal]==0.1.0a1'
.venv/bin/python -m modal setup

Let the Modal SDK store credentials in its own configuration. Never put tokens in a project manifest, source file, agent conversation, or Git repository.

2. Choose an environment and deploy

.venv/bin/python -m modal environment create <ENV>
.venv/bin/python -m modal deploy --env <ENV> -m modelforge_workbench.example.modal_app
.venv/bin/modelforge modal status --environment <ENV>

The status command checks only the local SDK and credential configuration. It does not contact Modal or verify the deployment.

3. Run with explicit billable confirmation

.venv/bin/modelforge demo run --executor modal --modal-environment <ENV> \
  --confirm-billable --state-root <STATE>
.venv/bin/modelforge runs list --state-root <STATE> --project synthetic-threshold

Deployment and execution can create billable resources. ModelForge does not enforce a budget or promise free execution.

4. Inspect and clean up

.venv/bin/python -m modal app list --env <ENV>
.venv/bin/python -m modal app logs modelforge-alpha-synthetic --env <ENV>
.venv/bin/python -m modal app stop modelforge-alpha-synthetic --env <ENV>
.venv/bin/python -m modal billing report

Stopping an app can interrupt calls. Check the exact app and environment first. Removing local state does not stop remote work.

Troubleshooting

  • If the SDK is missing, reinstall the modal extra in the same environment as ModelForge.
  • If credentials are unavailable, rerun .venv/bin/python -m modal setup and inspect the active profile. Do not copy token values into ModelForge.
  • If an app or environment is missing, verify the explicit --env <ENV> value and deploy the packaged app there.
  • If a call was accepted but the client stopped, use .venv/bin/modelforge demo recover-modal with the recorded run ID rather than starting a second run.
  • If local state and Modal disagree, inspect app logs and billing in Modal before stopping the exact app.
