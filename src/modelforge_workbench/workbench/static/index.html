First-use setup

Trusted local

The bundled synthetic project is ready offline. Real examples keep upstream source, datasets, and models outside ModelForge; inspect the read-only setup plan before choosing any acquisition or installation step.

  1. Review the plan .venv/bin/modelforge examples setup plan --example <example-id> --external-root <external-root> The plan shows destinations, upstream revisions, access and licence links, prerequisite status, supported actions, and the next commands. It performs no fetch or install. Pass --use <item-id>=<absolute-path> to inspect an existing local source, dataset, or model.
  2. Acquire only what you choose .venv/bin/modelforge examples setup fetch --example <example-id> --external-root <external-root> --confirm Fetching occurs only with explicit --confirm. Dataset access, gated models, credentials, and licence acceptance remain user-controlled prerequisites.
  3. Install project dependencies separately .venv/bin/modelforge examples setup install --example <example-id> --external-root <external-root> --confirm --install-requirements The isolated example environment is separate from the ModelForge base installation. Use --install-requirements only when the plan advertises a reviewed requirements file (currently Qwen); omit it to create an empty environment for manual host-compatible setup.
  4. Configure and register .venv/bin/modelforge project register --state-root <private-state> --config <local-config.json> Use the example README and generated plan to bind your existing or newly acquired local paths, then refresh this workbench.
